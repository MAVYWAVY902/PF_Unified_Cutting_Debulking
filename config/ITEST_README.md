# 交互测试：不同形状刀具（2026-10-19）

在 `cpp_sim/build` 目录下运行。建议每次都加 `--record`，把你的操作录下来。之后我可以用 `tool_bench --replay` 原样回放，逐帧测量你看到的现象。

```bash
cd ~/pf-shape-matching/cpp_sim/build
./pf_sim_gpu_viewer ../../config/itest_cube_scalpel.yaml --record ../trajectories/itest_cube_scalpel_01.csv
```

## 按键

| 操作 | 按键 |
|---|---|
| 旋转视角 / 平移视角 / 缩放 | 左键拖动 / 右键拖动 / 滚轮 |
| 打开 / 关闭刀具（关闭时刀不起作用，也不能移动） | **K** |
| 切换移刀模式（开启后鼠标移动的是刀，滚轮让刀前后移动；TeamViewer 下请用这个，按住空格在远程桌面里无效） | **M** |
| 旋转刀具（每按一次约 3°，绕刀具自身坐标轴；按住 Shift 反向） | X / Y / Z |
| 刀具复位（位置和朝向） | R |
| 暂停 | P |
| 显示表面 / 线框 / 粒子点 | 1 / 2 / 3 |
| 相机跟随 | T |
| 退出 | ESC |

一般的操作顺序：先按 **K** 打开刀具，再按 **M** 进入移刀模式，用鼠标把刀移到组织上方，然后慢慢往下移。想调整视角时，再按一次 **M** 切回相机模式。

## 所有切割配置都打开的新功能

| 开关 | 作用 |
|---|---|
| `local_split`（R1） | 簇按自身完好的边拆分。切口两侧真正分开，在张力下会张开 |
| `straddle_fracture`（R3） | 刀身插进两个粒子之间时，组织断开，不再出现"刀在组织里但组织完好"的情况 |
| `cut_features: auto` | 刀刃和针尖从刀具网格中自动提取 |
| `sdf_normal: trilinear` | 正确的刀具法向（R3 需要） |
| `debulking: false` | 只切不吸，不移除粒子 |

立方体边长 0.3 m，粒子间距约 10 mm。刀具都按比例放大过，使刀具尺寸和粒子间距的比例接近肿瘤场景。每帧约 50 ms，肿瘤场景约 110 ms（大约 9 fps）。

## 1. 立方体 + 手术刀：`itest_cube_scalpel.yaml`
刀片放大 12 倍：144 × 60 × 9.6 mm。刀刃在底边，沿 x 方向，刀尖朝下（−y）。

| 试一下 | 应该看到 | 不应该看到 |
|---|---|---|
| 刀刃朝下垂直切入 | 组织被压凹一下后切开；切口沿着刀片平面 | 刀片两侧大面积组织被破坏 |
| 切入后沿刀片平面（x 方向）拉动 | 切口沿刀片延长；刀身前方的组织被劈开 | 刀身插在组织里、周围组织却原样连着 |
| 切开后把刀拔出来 | 切口保持断开；重力下两侧可能略微分开 | 切口重新"长合" |
| 把刀片转成平放（按 X 约 30 次，大约 90°），贴着表面压一下再横向滑 | 组织只被压下去 | 平面压到的地方出现切口（侧面朝外的刀刃碰到鼓起的组织时，那一侧有少量切口是正常的） |
| 把立方体一角完全切下来 | 切下的那块成为独立的一块，在重力下掉落或移动 | 切下的那块仍然被"拴"在主体上 |

## 2. 立方体 + 穿刺针：`itest_cube_needle.yaml`
针放大 12 倍：半径 4.8 mm，长 180 mm，锥形针尖朝下。提取出的锋利特征只有针尖一个点。

| 试一下 | 应该看到 | 不应该看到 |
|---|---|---|
| 垂直慢慢刺入 | 表面先被压凹，然后刺破；针沿针道前进 | 针一碰就把一大片组织切开 |
| 刺入后横向移动 | 针身侧面推挤或劈开组织（针比粒子间距细，R3 会让被它挤到中间的组织断开） | 剧烈抖动、粒子被甩飞 |
| 拔出 | 针道保持断开 | — |

## 3. 立方体 + 剥离子（钝器）：`itest_cube_dissector.yaml`
放大 3 倍：213 × 31 × 7.8 mm。在 30° 阈值下几乎没有锋利特征（只有一段 2.3 mm 的边），所以刀刃本身基本不切。

| 试一下 | 应该看到 | 需要注意 |
|---|---|---|
| 平面朝下压 | 只推挤和压凹，不切开 | — |
| 薄边朝下压进组织 | 会把组织劈开 | 它 7.8 mm 厚，比 10 mm 的粒子间距还薄，所以在这个网格上相当于"薄"刀具。这是 R3 的设计行为："钝"与"薄"是相对于粒子间距而言的 |

## 4. 立方体 + 球形刀，减瘤对照：`itest_cube_sphere_debulk.yaml`
原来的超声吸引刀 / 减瘤模式，作为对照。这里**故意没有打开 R1**：减瘤模式下打开 R1 后，脱离的小碎屑要等 5 帧一次的碎片清理才会被移除，在这之前会被刀具甩飞（已经确认原因，等 3f 再解决）。

| 试一下 | 应该看到 |
|---|---|
| 压入后来回移动 | 和以前一样：刀具接触到的组织被吸除，形成空腔 |

## 5. 肿瘤 + 骨骼 + 手术刀（真实尺寸）：`itest_tumor_scalpel.yaml`
原来的 `tumor_cut` 配置，打开 R1 和 R3，刀刃改为自动提取（结果和原来手写的刀刃完全一致）。每帧约 110 ms，会比较卡，请慢慢移动。

| 试一下 | 应该看到 |
|---|---|
| 在肿瘤上切一道切口 | 切口跟着刀走；刀身不会"埋"在组织里面 |
| 切一道较深的切口 | 切口两侧能分开 |

## 已知限制（看到这些不是新问题）
- **刀具移动太快**（每帧超过一个粒子间距）时，被推开的组织也会快速移动。这是刀速本身造成的，要等第 5 步的虚拟耦合（限速）解决。R4 子步插值在这些配置里是关闭的。
- **刀刃附近约 0.45 mm 的盲区**（肿瘤尺寸下）：刀刃最薄的那一段比 SDF 网格单元还薄，碰撞看不到它。少量粒子会暂时停留在刀刃里，影响已经测过，很小（R2 的 GPU 精确几何推迟实现）。
- **切口渲染**：只要一个四面体含有任意一条断边，整个四面体就被隐藏，所以切口看起来有一个四面体那么宽。
- **完全脱离的单个粒子没有形状约束**（R1 之后的正常行为），会在重力下自由下落。
